# CityMETER Commercial District — first useful value

Build Card ของสัญญาการใช้งานครั้งแรกของเดโมนี้ ใช้ LDS 0.9.7 release `v0.9.7-owner.1` เอกสาร standalone `lds-0.9.7-landometer-standalone-r1` SHA-256 `d3085cbc0a50195f1cbf0c77b1d77c0d19b84364daf2948eb367348d65432d96` (สเกล `density.area` และ `count`) ไม่ใช่ใบรับรองความสอดคล้องทั้งระบบหรือผลผ่านทุกเบราว์เซอร์

## First Aha — AHA-01

**ความเข้าใจแรกที่มีประโยชน์:** ย่านกลางกินพื้นที่น้อยมาก แต่บางชุดข้อมูลกระจุกอยู่ในย่านเกินครึ่ง — ผู้ใช้เห็นทันทีว่าย่านกลางคือย่านแบบไหน และเริ่มสำรวจย่านที่เด่นหลายด้านได้โดยไม่ต้องเรียนรู้ตัวกรองก่อน

ข้อความเริ่มต้น (snapshot รุ่น 0.1.0): **“69% ของแบรนด์หรูที่มีพิกัดทั้งประเทศ อยู่ในย่าน 343 แห่ง ที่กินพื้นที่ 0.016% ของประเทศ”** — 237 จาก 345 จุดขาย · ย่านรวม 80.2 ตร.กม. จาก 515,416 ตร.กม. · ชิป: สำนักงาน 42% · ร้านกล้อง 40% · ฟิตเนส 38% ตัวเลขทั้งหมดคำนวณจากข้อมูลทุกครั้ง ไม่ใช่ค่าคงที่ใน markup

แผนที่เปิดทั้งประเทศแบบแผนผัง: หมุดของย่านตามหมวดของจุดเด่นแรก (Land · Location · Living ด้วยสีและรูปทรงของ LDS) ป้ายจังหวัดพร้อมจำนวนย่าน

**One useful action:** “เทียบ 3 ย่านที่เด่นหลายด้าน” เปิดแถบเปรียบเทียบ · “อ่านแผนที่ด้วย” เลือกชุดข้อมูล: ข้อค้นพบเปลี่ยนเป็นสัดส่วนของชุดนั้นและย่านที่แน่นที่สุด · เลือกจังหวัด: คิดในจังหวัดนั้น (กรุงเทพมหานคร: 82% ของจุดขายแบรนด์หรูที่มีพิกัดในจังหวัด อยู่ในย่าน 75 แห่ง ที่กินพื้นที่ 1.3% ของจังหวัด)

## Evidence cue and calculation

แหล่ง: `data/neighborhoods.json` (`datasets[].located`, `datasets[].byProvince`, `rows[].c`, `rows[].areaM2`) การคำนวณ: `buildOverview` (`js/profile.js`) บนย่านในขอบเขต · สัดส่วน = ผลรวม `rows[].c[ds]` ÷ `located` (หรือ `byProvince[province]`) · สัดส่วนพื้นที่ = ผลรวม `areaM2` ÷ พื้นที่จังหวัดทั้งหมด (หรือของจังหวัด) จากขอบจังหวัด production

## States

- ไม่พบย่านตามคำค้น: “ไม่พบย่านตามคำค้นนี้” + ล้างคำค้น / ดูทั้งประเทศ
- ชุดข้อมูลไม่มีจุดในขอบย่านเลย: “ยังไม่มี…ในขอบย่าน” พร้อมจำนวนจุดที่มีพิกัด
- แผนที่โหลดไม่ได้: ข้อค้นพบ แผง การเปรียบเทียบ และตารางยังใช้ได้ และหน้าบอกว่าส่วนไหนขาด
